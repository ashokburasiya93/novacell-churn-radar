# NovaCell Churn Radar

A weekly churn-risk call list for NovaCell's retention team (a synthetic ~4M-subscriber mobile operator). Every postpaid customer gets a **60-day churn probability** from an explainable ML model, the **top three reasons** behind it, and a **next-best action** chosen by expected value, including "no offer" when nothing pays back. An LLM then writes a short **call brief and SMS draft** from those facts only, and code checks every brief before an agent sees it.

> **All data in this repository is synthetic.** It was generated by `ml/generate_data.py` (seed 42) for a course project. No real company, customer or person is described. Persona quotes and business figures in the deliverables are made up and labelled as such.

- **Live app:** https://novacell-churn-radar.vercel.app (no sign-in)
- **Miro opportunity board:** https://miro.com/app/board/uXjVEQCGzx4=/

## The problem in one line

After a price rise, churn nearly doubled (5.1% to 9.3% in 60 days), but the call list still comes from one rule (contract ending soon or 2+ tickets) that flags 23% of customers at 12% precision and misses 71% of leavers, and every leaver is offered the same 20% discount.

 (21 inputs,       (logistic      (top 3, in      (top 10% = call list)    (risk × save rate ×

## Model results (August test cohort, trained on June)

| Approach | ROC AUC | Precision in top 10% | Recall in top 10% | Lift |
|---|---|---|---|---|
| Today's rule (flags 22.9% of customers) | 0.557 | 11.6% | 28.6% | 1.25x |
| **Logistic regression (chosen)** | **0.724** | **28.0%** | **30.1%** | **3.01x** |
| Gradient boosting (isotonic-calibrated) | 0.707 | 24.0% | 25.8% | 2.58x |

The simpler model held up better when the market moved (the June data had no price rise), and it explains exactly, so it was chosen and then retrained on June + August for this week's scores. Calibration: the June model under-predicted August churn by about half; the call list uses rank, and production retrains monthly.

**Fairness** (top 10% list, chi-square tests): age band p = 0.35 (flagged) / 0.13 (caught); gender p = 0.78 / 0.67, no significant difference. Region differs (p < 0.01) because East and Central have weaker coverage; region is not a model input, and the network-fix offer targets the cause.

## AI brief evals

Results are written to `evals/results/` by `scripts/run_live_evals.js` against the deployed app. Targets (PRD section 11): 100% of shown briefs safe, 100% right offer, 100% injection blocked, AI brief rate 90%+, p95 under 8 s.

## Run locally

```bash
pip install numpy pandas scikit-learn shap   # only to regenerate data and retrain
python3 ml/generate_data.py && python3 ml/train.py
node scripts/build_evals.js
npm test                                    # offline checker tests, no API calls
cp .env.example .env                        # add keys; never commit .env
node --env-file=.env scripts/dev_server.js  # http://localhost:3000
```

Without keys the app still works and shows rule-based briefs.

## Deploy (Vercel free tier)

1. Import the repo in Vercel (framework: Other, no build command).
2. Add `GROQ_API_KEY` and `OPENROUTER_API_KEY` as environment variables. Keys never go in the repo.
3. Deploy. The header badge shows the live models. To run evals, set `EVALS_ENABLED=true`, run `node scripts/run_live_evals.js <url>`, then remove the flag.

## Data note

All customers, numbers, ticket notes and offers are synthetic. Eight ticket notes contain prompt-injection text on purpose, to test the guardrails. Offer save rates are assumptions until an A/B test with a control group measures them.
